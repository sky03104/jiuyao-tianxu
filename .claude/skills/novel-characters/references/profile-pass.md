# 第二趟 · 生成角色卡

你是在為一部動畫改編準備製作素材。給你一個角色的名字、歸併後的全部觀察記錄、以及可引用的原文片段，產出一張完整的角色卡。

**只輸出 JSON，不要任何解釋、不要 markdown 圍欄。** 結構見 `schema.md`。

## 語言

呼叫方會給一個**報告語言** `lang`（預設 `zh`）。欄位分兩類：

| 類別 | 欄位 | 語言 |
| --- | --- | --- |
| **給人讀的** | `oneLiner`、`persona.*`、`voice.timbre/pitch/pace/accent/emotion/referenceHint`、`image.promptLocal` | **`lang` 指定的語言** |
| **餵給機器的** | `image.prompt`、`image.negativePrompt`、`image.tags`、`image.sheet`、`voice.prompt` | **永遠英文** |

機器欄位不跟隨 `lang`——影像模型和 TTS 引擎吃英文最穩，跟報告用什麼語言無關。

`image.promptLocal` 是英文出圖提示詞的本地語言譯文，給人看的。**`lang` 是 `en` 時省略它**，否則就是原樣重複。

**`voice` 沒有 `promptLocal`，這是有意的。** 音色的六項（`timbre` / `pitch` / `pace` / `accent` / `emotion` / `referenceHint`）本來就是本地語言的必填欄位，人審看那六項比看一段散文更快；再給一段中文譯文只會多出一個長得一樣的複製按鈕，使用者會把它喂進 TTS 引擎——**生產裡真踩過**。報告裡音色只留一條提示詞，就是喂引擎的那條。

## 硬規則

1. **一切基於觀察記錄。** 為了讓設定可用而不得不補全的部分，要跟原文保持一致，並且**標註出來**——中文報告加「（推斷）」，英文報告加 `(inferred)`，其他語言用該語言的等價說法。**只用一種標記，不要中英都加。**

2. **`persona.evidence` 只能放「可引用原文」區塊裡的字串，逐字照抄。** 不許翻譯、不許裁剪、不許把兩條合併、不許從觀察記錄裡另找。那個區塊是空的就返回空陣列。**注意：引文永遠保持原文語言，不跟隨 `lang`**——它是證據，翻譯了就不是證據了。

3. **`image.prompt` / `image.promptLocal` / `image.sheet` 裡絕對不許出現角色名、別名、作者名、作品名。** 影像模型對這些偏見極重，會畫成它記憶裡的角色而不是你的角色。描述這個人，不要叫他的名字。

4. **族裔、年代、地域以原文和使用者明確設定為依據，在 `image.prompt` 和 `image.sheet` 中體現。**

   這是上一條的另一半：名字不能寫，那這個人長什麼樣、是哪兒的人，就靠描述交代。已有明確的族裔、國籍和外貌設定時保留，不用泛稱覆蓋。

   三樣都要落到提示詞裡：

   | 要素 | 寫到這個程度 | 不要這樣 |
   | --- | --- | --- |
   | 人物泛稱與外貌 | 線索不足寫 `Asian`，臉型、五官、年齡依據人物資料分別描述 | 無依據自動指定具體族裔、國籍或眼形 |
   | 年代 | `early 20th century, Republican-era China` | `historical` |
   | 服飾與地域 | `coarse indigo cotton tunic, southern Chinese river town` | `traditional clothing` |

   **依據來自原文，不來自報告語言。** 報告出成日文不代表人物是日本人——`lang` 管的是誰來讀，不是故事發生在哪。原文沒明說就按文本推斷：人名用字、地名、稱謂、器物、節令、貨幣、飲食都是線索。

   推斷出來的內容按第 1 條標註在 `persona.appearance` / `persona.identity` 裡；**提示詞裡不標註**——那是給機器讀的，`(inferred)` 混進去會被畫進畫面。

   **族裔線索不足時預設使用「亞洲／Asian」**，不進一步指定區域族裔、國籍、漢族或單眼皮。不要把這個泛稱縮窄成區域標籤，也不要把同批人物寫成統一長相；臉型、五官、髮型、體態與年齡仍依據各自資料設計。年代、地域和服制有依據就寫具體，不能把族裔預設值當成年代依據。

   **原著是架空朝代時，寫它像什麼，不要寫它「是架空的」。** 「架空」「虛構」「某朝」
   `fictional` `alternate history` 這些詞說的是這個設定跟真實歷史什麼關係——那是一條元資訊，
   畫面裡沒有任何東西對應它，影像模型只能忽略，而它佔的是提示詞最前面那個位置。
   要寫的是可見的那一半：`Ming-inspired court robes, imperial Chinese capital`。
   這跟上一句不許寫 `(inferred)` 是同一條：**關於設定的話不進提示詞，設定本身才進。**

5. `image.prompt` 是**單張表現性插畫**（不是技術圖，可以放開打光）：四分之三視角半身、純中性背景、柔和方向主光 + 冷調補光、淺景深、面部最實。

   **提示詞裡不寫畫風。** 不要出現「半寫實厚塗」「扁平向量卡通」「painterly rendering」這類說法，也不要為了統一而在每條提示詞裡重複同一句風格描述。畫風是出圖那一刻才定的——同一批角色可能今天出寫實、明天出國漫，而提示詞裡寫死的那一句會跟當時選的風格打架，模型兩頭都不聽。提示詞負責**這個人是誰**，風格由呼叫方在出圖時附加。

   **寫這個人獨有的東西，不是寫渲染品質。** 骨相、臉型、五官比例、髮際線走向、體型和姿態；**左右略不對稱**的眼瞼與眉毛；年齡留下的痕跡（老年斑、皮膚鬆弛，**皺紋順著表情肌走**——法令紋、魚尾紋、抬頭紋，不是隨機刻線）。這些換任何畫風都成立，而「可見毛孔」只在寫實那一檔成立。

   **畫的是這個人的常態造型，不是某一場戲的裝束。** 設定圖是全劇每個鏡頭都要回頭參照的那一張——釘在某個場合上，它就只覆蓋了部分戲。寫他平時就是這樣的那一身：皇帝的常態可以是朝服，船伕的常態是那件洗白的短褐，各按各的來。臨時換上的禮服、夜行衣、婚服、喪服屬於分鏡，不進角色卡。

   **不要把「便裝」「常服」「朝服」這類場合標籤寫進 `image.prompt` 和 `image.sheet`。** 形制已經排在第一位了（圓領袍、直裰、曳撒、褙子），場合標籤跟在後面不增加任何畫面資訊，只增加一個「這人只在這個場合這樣穿」的承諾，而設定圖要管全劇。皇帝那身寫成「盤領窄袖、金織盤龍補、翼善冠」，不寫「朝服」。

   **每個人要有一處識別錨點：拿掉它就認不出是誰。** 五官清單誰都寫得出來，十個人寫完會像同一個模板填了十遍。讓人物分明的是那一處只屬於他的東西——左眼的灰白翳、梳順的長鬚配一根烏木杖、永遠搭在刀柄上的右手、壓不平的那一綹碎髮。**判據跟場景錨點同一條：可畫、可認、可核對。**「氣質儒雅」不是錨點，「拄烏木長杖、單手穩握」才是。每條提示詞至少有一處，而且要跟這個人的經歷對得上。

   它可以就是下面那一處使用痕跡，也可以是身體、髮式或隨身物上的固定特徵——兩條規則說的是同一件事的兩面：**只屬於他的那一處要有，不屬於他的那幾處不要堆。**

   **身份必須落實成可見設計，不能只留在 `persona.identity`。** 先從觀察記錄確定人物的身份、經濟條件、職業和年齡，再選擇與年代相符的服裝輪廓、面料與維護狀態、剪裁層次、髮式配飾、鞋履和體態。`image.prompt`、`image.promptLocal` 與 `image.sheet` 的主體描述必須保留同一組身份線索；不能一處寫貴族繼承人，另一處只剩泛泛的年輕讀書人。

   **服飾按「形制 → 面料 → 收邊配飾 → 使用痕跡」的順序寫，形制排第一。** 第一項必須是**這個朝代裡能讀出身份的具體款式名**——圓領袍、直裰、曳撒、貼裡、褙子、襴衫之類——不能只寫「長袍」「交領長袍」這種任何人都能穿的通用輪廓。「貴族繼承人」「世子」「書生」是身份的名字，畫面上沒有對應物；款式、帶銙、冠式、織法才有。

   順序不是排版潔癖：出圖前這段要轉成英文，而**丟東西總是從尾巴開始丟**。把唯一能讀出身份的那一項放在句首，它才活得下來。實測把「素玉小冠」和「細密暗紋絲綢」放在中段，轉英文之後兩個都沒了，只剩一件誰都能穿的素袍。

   **剋制不等於寒酸，身份也不等於華麗。** 貴族便裝可以素淨，通過合體剪裁、衣料品質、精細收邊、恰當冠飾和從容體態體現；有原文依據的落難、喬裝、勞動或服喪造型仍按當時處境畫，不要為了顯貴強加金飾、官服或權力姿態。臉型與骨相不承擔社會階層判斷。

   **體態是有主的，不是預設值。** 雙手收在腰前、拱手、垂手侍立這幾個姿勢在畫面上就是「在等人吩咐」，**只有當這個人此刻確實在等人吩咐時才能寫**。人物文靜、年輕、是女性、正在讀書，都不是理由。沒有明確理由時寫他自己的習慣動作——按著書頁、負手、把玩隨身物件、單手撐案。

   **整體服飾與劇情細節分別約束、同時成立。** 整體形制、材質、剪裁、層次表達身份與場合，區域性磨損、墨跡、素飾、具體手部姿態等表達劇情與使用習慣。袖口區域性磨白不等於整件衣袍粗舊，素簪不等於侍女裝，收手姿態不等於僕從身份；不能把一個區域性細節擴充套件成整個人的身份結論，也不能為了強化身份刪除明確的劇情細節。更新已有角色卡時讀取現有造型資料，保留這些細節並補足整體設計。只有確實互斥的要求才標為衝突，不以單個細節或階層刻板印象替代判斷。

   **服裝寫具體材質與使用狀態，不寫渲染品質。** 保養良好、挺括平整、細密織物與精細縫邊同樣是生活細節。推斷的服裝設計按第 1 條標註；不要把推斷寫成原文事實，也不要把常態造型和臨時裝束拼成一套。

   **使用痕跡最多一處，而且要說得出是誰造成的。** 磨損、補丁、洗白、汙漬、墨跡都不是預設必填項——原文、職業或當前處境說不出來由就不寫。一處是細節，三處是另一個人：袖口磨白 + 食指墨跡 + 布靴堆在一起，畫出來就是個抄書的，不管你在前面把「侯府世子」寫了幾遍。

   **交付前做身份—外觀語義自檢。** 對照觀察記錄和 `persona.identity/appearance`，檢查三份 image 文本是否丟失關鍵身份線索、無依據降低衣著品質或改變年齡/職業；不一致就同步修正三份描述。這個判斷不能用「貴族必須華服」「有補丁就是僕人」的詞表代替。指令碼的結構校驗不能證明這些語義一致。

   `negativePrompt` **只禁畫面缺陷，不禁畫風。** 不要寫 `photorealistic` / `3d render` / `anime` 這類風格詞——它們會跟出圖時選的畫風正面衝突。該禁的是「假」和「錯」：所有角色同臉、幼態大眼、過度磨皮、完全對稱的臉、沒有高光的死眼、頭盔狀無碎髮的頭髮、僵硬的人臺姿勢、多指與肢體錯亂。

6. **`image.sheet` 是角色設定圖——一張 16:9 橫構圖，內部分三個區。** 這是給出圖模型的完整版面指令，比例要寫死，不能讓它自由發揮：

   ```
   ┌──────────┬────────────────────────────┐
   │          │   正視    側視    背視       │
   │  半身像   │                            │
   │ （證件照） ├────────────────────────────┤
   │          │  細節 · 細節 · 細節 · 細節   │
   │   ~34%   │                            │
   └──────────┴────────────────────────────┘
              16:9
   ```

   | 區 | 內容 |
   | --- | --- |
   | **左** 約 34% | **半身像**：頭肩，正面，居中，像證件照。臉畫全、畫細，這是面部設計的基準。**兩側肩膀完整**，底邊**齊平直切** |
   | **右上** | **全身三檢視**：正視 / 側視 / 背視並排，共用一條地平線 |
   | **右下** | **細節條**：4–5 個關鍵細節的小特寫，等距排一行，明顯小於全身像 |

   三個區之間用**細線**分隔。整張純白背景、四周留白均勻。

   **光照要分割槽寫**，這是設定表和寫實的矛盾點：
   - **左欄半身像**：左上方柔和方向主光、衰減自然，下巴下方 / 眼窩 / 領口與脖頸交界處有環境遮蔽——臉要有體積
   - **右側兩區**：平光正交、無方向主光、無投影——**摳圖和量比例全靠它**

   寫死成 `LIGHTING IN THE LEFT ZONE ONLY: ...` 和 `LIGHTING IN THE RIGHT ZONES: flat even orthographic lighting ...`。全圖統一平光會讓整張顯得「插畫感」，全圖統一打光又沒法摳圖。

   **比例是這個版面最容易崩的地方。** 提示詞裡必須寫死：三個全身像等高、頭身比一致、四肢長度和頭身比正確、雙腳踩在同一條地平線上、頭頂和腳下都留出空隙，**絕不能為了塞下別的東西把人物拉伸或壓扁**。

   **細節放不下怎麼辦**：底部一行排不下就沿畫布右緣往下延伸成一豎列。**但永遠是細節讓位，不是人物讓位**——提示詞裡要明說 `the detail studies give way, not the figures`。

   **一張圖裡只能有一個長相。** 三檢視的面部與左欄半身像一致——同樣的五官、髮型、表情。左欄是基準，右欄照著它畫。

   提示詞裡必須逐條寫明：`ONE 16:9 landscape canvas`、`LEFT ZONE ... about 34% of the canvas width`、`RIGHT-TOP ZONE`、`RIGHT-BOTTOM ZONE`、`thin hairline rules`、`PROPORTIONS ARE CRITICAL`、`the detail studies give way, not the figures`。

7. `voice.prompt` 是給 TTS 音色設計引擎的：描述**樂器本身**，不是某一句臺詞的演繹。性別、聽感年齡、音色、音高區間、共鳴、氣聲、語速、節奏、口音、能量、預設情緒。

   **音色設計是一個靜態的聲音身份。** 引擎要的是「這把嗓子長什麼樣」，不是「他這句話怎麼說」。四類東西寫進去就會讓效果變差，生產裡逐一踩過：

   | ✗ 不許寫 | 例子 | 為什麼 |
   | --- | --- | --- |
   | **文學比喻** | 「字與字之間像在秤上掂銀子」「一張聽得見笑、卻不能信的嘴」 | 引擎對映不到任何聲學引數，純粹稀釋有效資訊 |
   | **表演指導** | 「威脅時從不提高音量——反而更輕更慢」 | 那是導演給演員的話。音色不隨劇情變 |
   | **條件分支** | 「公堂場合能切換成過得去的官話」 | 一個 voice 只有一種口音。寫「切換」只會讓輸出不穩定 |
   | **引號臺詞** | 「殺意藏在『規矩就是規矩』這類客套話裡」 | 有些引擎會把引號裡的字當成要朗讀的內容。**`validate` 攔這一條** |

   四條裡只有引號臺詞設了門——它判定乾淨。另外三條靠寫卡的自覺：**關鍵詞掃描會誤傷正常描述**（「說話時」「低音區」都含「時」「區」），而誤攔的門比沒有門更糟。

   **寫成緊湊的引數串，不要寫成散文。`validate` 卡 400 字元。** voice design 引擎吃的是引數密度，鋪陳的英文散文會把引數稀釋掉——生產裡拿同一個角色實測對比過 500 字散文與 230 字引數串，**後者明顯更好**。上限 400 是量出來的：自帶樣例四個角色 218–245 字元，被判為冗餘的散文版 490–514，中間餘量很大。它攔的是「寫成小作文」，不是「寫得細」。

   固定的引數順序，照抄這個形狀：

   ```
   〔年齡性別〕, 〔音色〕, 〔音區〕, 〔共鳴/支撐〕, 〔動態範圍〕.
   〔音量〕, 〔語速〕, 〔語調習慣〕. 〔口音〕. 〔預設情緒〕.
   ```

   ```
   19-year-old female, light breathy soprano, mid-to-high pitch, thin chest support,
   narrow dynamic range. Quiet volume, slightly hesitant pace, rising inflection at
   phrase ends. Standard Mandarin, no regional accent. Tentative and watchful.
   ```

   **從頭到尾都在描述這把嗓子，一句戲都沒有。**

   ### 這條提示詞是給哪種引擎的

   **只有「文字直接設計音色」那一類引擎吃它**，別的引擎給了也沒用：

   | 引擎 | 吃不吃 `voice.prompt` |
   | --- | --- |
   | **Qwen3-TTS Voice Design** · ElevenLabs Voice Design · MiniMax speech | **吃**。整段直接喂 |
   | CosyVoice 2/3 instruct | **不吃音色**。它的 instruct 是在零樣本克隆之上加風格控制，音色仍然來自參考音訊 |
   | IndexTTS / IndexTTS2 | **不吃**。音色只來自參考音訊；IndexTTS2 的文本通道只管情緒，可以喂 `voice.emotion` 那一句 |

   用克隆系引擎的話，這條提示詞幫不上忙——要靠 `referenceHint` 與六項去挑參考音訊。**這不是提示詞寫得不好，是那類引擎根本沒有這個入口。**

8. **同一批角色之間要能區分開，這條現在有門。** 會給你同批其他角色的名字，別把他們的長相和聲線做成一個樣。

   **`validate` 會逐對算 `image.prompt` 與 `voice.prompt` 的詞級雷同度，超過 75% 直接報錯並點名那一對。** 閾值是量出來的：自帶樣例四個角色兩兩最高 39%，而「只改年齡與衣服顏色」的雷同用例是 98%，中間餘量極大。

   **最容易踩的形態不是照抄，是偷懶**：個體描述寫得短，剩下全是真實感樣板（毛孔、毛細血管、次表面散射、虹膜纖維）與固定的構圖光照尾巴。兩個年齡性別接近的角色一這麼寫，出來就是同一個人。**區分度要落在個體描述那一段**——臉型、五官比例、體態、衣著的具體材質與磨損、以及這個人身上獨有的那一處細節。

   `image.sheet` 刻意不查：三分割槽排版規範是大段固定文本，真實角色之間本來就有 63% 重合，設門必然誤攔。
