## 1. 客戶端專案架構具體規劃

- **資料夾結構**（`Assets/_Project/`下）：
  - `Core/`：底層通用工具、依賴注入與事件總線基礎設施。
  - `Net/`：Photon Fusion封裝、NetworkRunner狀態同步接合層。
  - `Combat/`：**純表現層**——特效/動畫/受擊反饋，訂閱伺服器事件，不做傷害計算或
    判定邏輯。
  - `UI/`：介面與HUD，採MVVM或類似模式，畫面與邏輯分離。
  - `Economy/`／`Guild/`：經濟/公會資料展示層，不含交易計算邏輯。
  - `Config/`：資料驅動配置讀取模組（見第3節）。
  - `Art/`／`Scenes/`：美術資源與場景。
  - `Editor/`：策劃/美術工具（配置編輯器、預覽工具）。
- **模組邊界原則**：UI不直接引用戰鬥實作，只透過介面/事件溝通；渲染與表現層嚴格唯讀
  伺服器下發的狀態，不計算任何傷害或判定，確保呼應01/03已定案的伺服器權威精神。
- **資產管理**：採用Addressables進行動態資源加載與熱更新，配合LOD依相機距離與
  06已定案的Zone Interest Management範圍動態卸載/加載高模與特效。

## 2. 伺服器端架構具體規劃

- **權威層（Dedicated Server / Headless Unity + Fusion）**：
  - 內部戰鬥判定採雙迴圈設計（呼應03已定案的頻率解耦）：
    - `DecisionLoop`：30~60Hz固定tick，執行命中判定、技能/靈印/屬性克制結算、
      冷卻與資源扣減、狀態機更新（含韌性/破綻）。
    - `SyncLoop`：10~15Hz對外廣播，將`DecisionLoop`結果打包為增量快照（delta）
      下發客戶端。
  - **延遲補償/時間回溯**：伺服器保留短期歷史狀態（約100~250ms），依客戶端上傳的
    操作時間戳做回溯判定，只接受合理延遲窗口內的輸入，超出窗口丟棄或降級處理。
  - **09已定案BOSS韌性條/破綻窗口實作**：伺服器維護`韌性值/上限/回復延遲/破綻計時器`
    狀態機，每次有效削減判定在`DecisionLoop`扣減，歸零時寫入「破綻中」狀態並開啟計時器，
    `SyncLoop`廣播狀態變化事件與剩餘時間；傷害倍率加成同樣在伺服器內計算，客戶端僅接收
    結果播放特效。
- **輔助層**：Matchmaking/Session導流服務，只負責房間分配與連線導流，不參與戰鬥判定。

## 3. 資料驅動配置表具體格式規範

- **主格式**：策劃以Excel/Google試算表編寫，透過管線工具（如Luban或團隊自研腳本）
  一鍵匯出為：
  - 執行期用二進位/JSON資料（客戶端與伺服器共用同一份canonical資料，確保雙端一致）。
  - Unity端另生成對應C#資料類別與ScriptableObject包裝，方便策劃在編輯器內預覽與微調。
- **版本管理**：
  - 每份配置檔含`configVersion`／`schemaVersion`／`checksum`欄位。
  - 配置存於獨立版本庫，發布走CI流程：策劃提交→自動化靜態檢查（ID重複、必填欄位、
    數值範圍）→產生版本號→打包發佈→客戶端/伺服器啟動時比對manifest版本，
    不一致才觸發熱更新。
- **策劃獨立編輯（不需工程師介入）**：
  - 提供表格模板＋Schema校驗規則，策劃在試算表內編輯，匯出前自動跑格式檢查並標示錯誤
    儲存格；同時提供模擬戰鬥/預覽工具供策劃直接測試技能/BOSS機制數值，無需工程師寫測試碼。

## 4. 後端服務拆分（呼應14經濟系統/拍賣場資料一致性）

- **拆分原則**：模組化單體起步，核心一致性需求高的部分優先獨立：
  1. **帳號/驗證服務**：登入、角色資料、權限。
  2. **戰鬥/副本服務**（即時，權威層）：不做持久化交易計算，只回傳「結果事件」給後端。
  3. **經濟與拍賣場服務**（呼應14已定案雙幣制/拍賣場）：**強一致性優先**，
     採用交易/訂單狀態機（`上架→鎖定→成交/取消→結算`）搭配資料庫事務（ACID）或
     Try-Confirm-Cancel模式，確保曜金/物品不會重複結算或消失，避免財產類問題透過
     跨服務分散事務處理。
  4. **公會/社交服務**（呼應13已定案）：可與世界狀態服務共用資料庫，但邏輯獨立，
     允許最終一致性（如排行榜/通知延遲）。
- **一致性策略**：戰鬥服務只發出`RewardGranted(玩家, 獎勵列表, 副本ID, 時間戳)`事件，
  經濟服務依副本ID做冪等處理（Idempotency Key），避免斷線重連導致獎勵重複發放。

## 5. 資安與防作弊具體技術手段（呼應03/09伺服器權威精神）

- **零信任輸入**：客戶端僅傳送「操作意圖」（移動向量、技能ID、目標ID、時間戳），
  絕不傳送計算結果；所有傷害/命中/冷卻/資源計算一律在伺服器`DecisionLoop`完成。
- **伺服器合法性校驗**：
  - 位移速度校驗（移動距離不得超過技能允許的最大速度×時間差，超標直接修正拉回）。
  - 冷卻與資源即時校驗（伺服器獨立維護技能冷卻與靈力/氣力狀態，不信任客戶端回報）。
  - 命中合法性（距離/視線/無敵幀狀態校驗），呼應03已定案延遲補償邏輯。
- **傳輸層防護**：連線憑證由後端簽發（如JWT/Session Token），Photon Fusion連線層啟用
  加密與序號防重放機制，並對輸入頻率設速率限制，超量視為異常直接丟棄或觸發風控標記。
- **客戶端加固（輔助，不取代伺服器權威）**：IL2CPP編譯搭配程式碼混淆、關鍵記憶體數值
  加殼處理（防記憶體掃描/修改工具）、資源包簽章校驗防止本地資源被竄改。
- **經濟系統防護**（呼應14已定案RMT防範）：所有交易走原子化操作與審計日誌，
  拍賣場交易紀錄可回放；關鍵結算公式與版本號不下發客戶端，伺服器端二進位/加密配置
  為唯一真相來源，防止逆向竄改。
