## 1. 跨媒體定位

《九曜：天墟》同時承載以下產出形式，共用同一套正式世界觀（以21世界觀總綱為準）：

- MMORPG／RPG 遊戲（正史載體）
- 長篇動畫／遊戲Cinematic式動畫
- YouTube長片
- YouTube Shorts／抖音短影音
- 遊戲PV／角色PV
- 開發紀錄

## 2. 三種敘事層與「遊戲正史／動畫補完」規則

### 2.1 遊戲：玩家視角（正史）

- 玩家是主要行動者，透過探索/戰鬥/任務逐步認識世界。
- **一切世界觀真相、勢力立場、境界/系統規則，以遊戲正式文件（00/02~21）為準。**

### 2.2 動畫：世界／角色視角（補完）

- 展示玩家看不到的事件（NPC背後的動機、勢力內部會議、角色的過去）。
- 深化角色動機，補充勢力與歷史細節。
- 可以提前埋伏筆，**但不得直接破壞遊戲主線的謎團節奏**——動畫可以讓觀眾「感覺到
  更多」，但不能替玩家把遊戲裡還沒解開的謎題直接說破。
- **正史優先權規則**：動畫內容若與遊戲正式文件衝突，一律先修改動畫；只有使用者
  明確決定重新鎖定正式世界觀時，才反過來修改遊戲文件。動畫不擁有否決遊戲正式
  規格的權力。

### 2.3 短影音：內容入口

- 角色片段、世界觀解說、Boss介紹、開發幕後、動畫精彩片段的短版本剪輯。
- 目標是讓沒玩過遊戲、沒看過動畫的人也能被吸引，逐步導向動畫或遊戲本體。

## 5. 共用資產規範

- **原則**：遊戲、動畫、PV、短影音**優先共用同一套3D資產**——角色模型、骨架、
  Facial/表情、動畫Clip、武器、場景、怪物、Boss、VFX、材質，禁止為動畫建立與
  遊戲完全不同且無法共用的主要角色資產，除非有明確藝術或技術理由並經使用者確認。
- **共用不等於同一套渲染管線直接輸出**：遊戲端需要即時運算（手機硬體限制，見
  第6.3節風險提示），動畫端可以用同一套骨架/模型做**離線算圖或更高規格的即時
  Cinematic預覽**，兩者輸出品質不同，但底層資產是同一份，避免美術資源重工。
- **需要另外處理的部分**：動畫用的高精度表情/口型資料（見第6節）、鏡頭專用燈光/
  後製，屬於「附加在共用資產上的動畫專屬層」，不需要也不應該塞進手機執行時
  的即時渲染路徑。

## 6. Cinematic技術需求（對17_TECH_ARCHITECTURE的建議）

**本階段只盤點需求，不實作完整動畫系統**（呼應HANDOFF-003第八節Phase0範圍限制）。

### 6.1 建議方向

- **Timeline／Sequencer類系統**：Unity Timeline可同時服務「遊戲內過場」與「離線
  算圖動畫」兩種輸出，建議提早在17_TECH_ARCHITECTURE的`Art/`與新增的`Cinematic/`
  資料夾規劃中預留這條路徑，避免之後為動畫另起一套工具鏈。
- **角色表情控制**：建議角色骨架從一開始就包含基礎表情骨骼/BlendShape，
  即時遊戲只用到「戰鬥/待機/基本情緒」等級的簡化表情，動畫端在同一套骨架上
  疊加更精細的表情資料，共用根骨架但不共用精細度。
- **鏡頭資料**：Cinematic鏡頭語言（運鏡/景深）與遊戲內運鏡（過肩/戰鬥鏡）可以
  共用同一套Camera Rig基礎元件，減少維護兩套鏡頭系統的成本。
- **場景燈光／後處理**：遊戲即時渲染受手機效能上限，動畫可用更高規格的離線
  燈光/後處理，但場景幾何體本身應共用，只是燈光/後製參數在動畫端獨立疊加，
  不影響遊戲端的效能預算。
- **NPC／Boss Cinematic行為**：建議NPC/Boss的動畫Clip在製作時就同時考慮「戰鬥
  即時播放」與「Cinematic演出」兩種用途的可重用性，避免各做一套。
- **資產共用邊界**：遊戲內過場（低規格、需即時運算）與獨立動畫輸出（高規格、
  離線算圖）**共用模型/骨架/基礎動畫Clip，但不共用最終渲染管線**，這是
  第5節「共用不等於同一套渲染管線」原則在技術面的具體落地。

### 6.2 對17_TECH_ARCHITECTURE的具體修改建議（尚未動手改17，先提出待確認）

建議在17新增一小節「Cinematic資產共用邊界」，註明：
1. `Art/`資料夾下新增`Cinematic/`子資料夾，存放動畫專屬的高精度表情資料、鏡頭
   Sequence與離線燈光設定，與遊戲即時渲染路徑（`Combat/`表現層）明確分離。
2. 角色骨架規格從第一批角色製作起就統一納入表情骨骼，避免後續為動畫重新綁骨。

**這是建議，不是本次任務直接動手修改17的機制數值**——17目前沒有跟本建議衝突的
既有內容，只是缺少這塊規劃，屬於「補充」而非「修改已定案規格」。

### 6.3 技術風險提示（誠實揭露，非阻塞）

目前**沒有任何已定案文件訂出手機硬體規格/角色面數與貼圖預算上限**
（已檢查16_ART_DIRECTION與17_TECH_ARCHITECTURE，兩者都沒有具體數字）。這代表
「共用資產」計畫目前無法確認動畫端要求的表情精度/鏡頭特效，會不會反過來被
美術團隊誤用在遊戲即時渲染路徑上，造成手機端效能問題。**建議在正式製作角色
資產前，先由17補一份具體的手機效能預算基準（面數/骨骼數/材質數/Draw Call
上限），本文件的共用資產規範才有具體數字可以遵守，否則「共用」容易變成
「動畫規格向下相容不良，反而拖累遊戲端效能」**。這點不屬於HANDOFF-003本次
任務範圍，但既然發現了就一併提出，供後續排入17的補完項目。

## 7. 短影音內容策略（四類）

1. **角色短篇**：單一角色的小片段（如EP04厲若楓收到家書但沒拆開的畫面），
   吸引觀眾好奇角色背景，導向動畫本體。
2. **世界觀短篇**：一分鐘內解釋「什麼是曜脈」「天玄院是什麼」等基礎設定，
   服務完全沒接觸過本IP的新觀眾。
3. **Boss／戰鬥短篇**：赤瞳妖將等Boss的機制/氣勢展示片段，可直接取材遊戲內
   Cinematic或動畫EP06片段，強化「這隻怪物很強」的印象。
4. **開發紀錄短篇**：美術/技術/劇情開發過程的幕後片段，服務對「這款遊戲是怎麼
   做出來的」有興趣的觀眾，同時是低成本、高更新頻率的內容來源。

**目標**：讓沒有玩過遊戲、沒看過動畫的人也能看懂，並自然導向《九曜：天墟》
世界觀與遊戲本體，形成「短影音→動畫→遊戲」或「短影音→遊戲→動畫」的雙向導流。

## 8. Phase 0範圍聲明

本文件**不要求現在製作完整動畫**，也不影響Phase 0-A/0-B遊戲技術Spike的優先權
